# Contributing to FinSight

Thank you for your interest in contributing to FinSight.

## Getting started

1. Fork or clone the repository.
2. Review the README for the project architecture, tools, and setup requirements.
3. Set up the required Python packages and external services for the component you want to work on.
4. Create a separate branch for your changes.

## Making changes

- Keep changes focused and clearly documented.
- Follow the existing Python and SQL naming conventions.
- Do not commit credentials, passwords, API keys, or private configuration.
- Do not commit generated logs, temporary files, or large datasets without a clear reason.
- Use synthetic or appropriately licensed data for examples.
- Document new configuration settings and external service requirements.

## Testing

- Test the affected scripts or SQL workflows in an environment with the required dependencies and services.
- Validate data schemas, record counts, and outputs where applicable.
- Clearly document any tests that could not be run because of missing services or infrastructure.

## Submitting changes

1. Confirm that your changes are limited to the intended files.
2. Review the diff before committing.
3. Include a clear commit message describing the change.
4. Explain the purpose of the change and any relevant validation in your pull request.

## Project scope

FinSight is an educational data engineering and analytics portfolio project. Contributions should not represent its fraud rules, risk scores, or reporting outputs as validated for production banking use.
